## 最初に行うこと

1. `git status`、現在のブランチ、`origin/main`との差分を確認する。
2. 未コミットの変更がある場合は、ユーザーの作業を混ぜずに更新を中止し、状態だけ報告する。
3. 作業ツリーがきれいな場合だけ `git pull --ff-only` を実行する。
4. README、既存コンテンツ、直近のコミット、本番サイトを確認し、同じ改善を繰り返さない。

## 毎日の数値確認

利用できる場合は、ログイン済みブラウザを使って次を確認する。

- Google Search Console: `https://tabijitakulist.com/` の直近7日間のクリック数、表示回数、CTR、平均掲載順位、上位クエリ、上位ページ
- Cloudflare Web Analytics: `tabijitakulist.com` の直近24時間の訪問数、ページ閲覧数、主要ページ、Core Web Vitals

前回値があれば増減を比較する。取得できない場合は推測や古い値の使い回しをせず、「取得不可」と理由を明記する。ログイン、本人確認、APIトークン発行などユーザー本人の操作が必要な場合だけ、最後の報告に必要事項を1件ずつ簡潔に書く。

## 改善方針

数値とサイトの状態から、効果が高く安全な改善を1件から3件選ぶ。次を優先する。

- 旅行タイプ、季節、同行者、目的地に応じた持ち物リストの実用性
- 入れ忘れを減らすチェック機能、保存、印刷、共有、再訪時の使いやすさ
- スマートフォンの読みやすさ、操作性、アクセシビリティ
- 検索意図に合う文章品質、タイトル、説明、内部リンク、構造化データ
- 表示速度、エラー、壊れたリンク、重複ページの改善

更新するためだけの更新、日付だけの変更、根拠の弱い大量ページ生成、薄い文章、他サイトの模倣は行わない。十分な改善余地がない日は変更しなくてよい。

## 実装と公開

1. 既存の設計と実装パターンに合わせて変更する。
2. `npm.cmd run check` と `npm.cmd run build` を実行する。
3. UIを変更した場合は、可能な範囲でPC幅とスマートフォン幅をブラウザ確認する。
4. `git diff --check`、主要導線、内部リンク、canonical、robots.txt、sitemapを確認する。
5. すべて成功した場合だけ、内容が分かるコミットを作成して `main` へpushする。
6. Cloudflare Pagesの反映後、`https://tabijitakulist.com/` が正常に表示されることを確認する。

ドメイン購入、課金、広告契約、個人情報入力、認証情報の変更、CloudflareやGoogleの権限変更、破壊的なGit操作は行わない。
