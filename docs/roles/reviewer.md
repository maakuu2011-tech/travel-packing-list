# レビュー担当

読むもの: 分析メモ、採用案と完了条件、実装差分、検証結果。

1. 差分が採用範囲に収まり、利用者の持ち物リスト作成とスマートフォン操作を損ねないか確認する。
2. 旅行情報の出典・確認日、検索意図、内部リンク、canonical、sitemap、構造化データ、広告表記の整合を確認する。
3. KPI の期間・欠測の扱い、ビルド、操作確認、本番確認の計画を評価する。
4. 指摘を「公開前に修正」「後日確認」「問題なし」に分け、公開可否を返す。公開前に修正する指摘が残れば差し戻す。

可能なら実装とは別の担当が確認する。独立した担当を使えない場合はその事実を最終報告に記す。
